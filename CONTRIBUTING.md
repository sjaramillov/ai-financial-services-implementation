# Contribuir

Proponer cambios mediante pull request. Explicar el control afectado, el comportamiento anterior y posterior, las pruebas realizadas y las limitaciones que permanecen.

- Usar datos sintéticos y placeholders para infraestructura.
- Mantener separados los ejercicios de operaciones y evaluación de candidatos.
- Cambiar el JSON fuente para regenerar un visor Archify; no editar su HTML generado.
- Acompañar cambios en autorización, estados o recuperación con pruebas de fallos y reintentos.
- Ejecutar los comandos de verificación del README antes de enviar el cambio.
- No ejecutar Terraform ni conectar un core como efecto de una prueba o de CI.

La documentación debe identificar una capacidad como implementada, simulada o propuesta. Una prueba de formato o un diagrama no demuestran seguridad operativa.
